# LocalRemote 0.5.1

## Обновление с LocalRemote 0.4

В версии 0.5 изменён протокол передачи файлов. Обновите **оба компьютера**: дождитесь завершения текущей передачи, выберите **Выход** возле часов и замените всю папку программы новой сборкой. Код доступа сохраняется. Если путь папки не меняется, повторная настройка автозапуска не требуется; при смене пути сохраните автозапуск и обновите правило брандмауэра.

## Обновление с NewAnyDesk

Закройте старую программу через **Выход** возле часов на обоих ПК. Перенесите всю новую папку `LocalRemote` в постоянное место и запустите `LocalRemote.exe` под прежним пользователем Windows. Ключ хоста и сохранённое подключение автоматически копируются из `%LOCALAPPDATA%\NewAnyDesk` в `%LOCALAPPDATA%\LocalRemote`, если новых настроек ещё нет. Старые коды `newanydesk://` принимаются; новые начинаются с `localremote://`.

На стриминговом ПК заново нажмите **Сохранить автозапуск** и **Разрешить доступ в брандмауэре…**. Это обновит путь EXE и удалит прежние записи NewAnyDesk. Копирование файлов приложения само по себе не меняет автозапуск. После первого переноса удалённый или забытый ключ из старой папки повторно не восстанавливается.

Удалённое управление своим вторым ПК в домашней сети. Один и тот же EXE запускается на обоих компьютерах. Подключение Ethernet ↔ Wi-Fi работает через один роутер, если на нём выключена изоляция Wi-Fi-клиентов и оба ПК доступны друг другу.

## Установка на двух ПК

1. Закройте старую версию через **Выход** в меню значка рядом с часами и скопируйте **всю папку `dist/LocalRemote`** на оба ПК. В архиве `LocalRemote-win-x64.zip` находится такая же готовая папка. Для видео рядом с `LocalRemote.exe` необходим `ffmpeg.exe`; переносите папку целиком. Сборка для Windows 10 22H2 / Windows 11 x64 включает .NET; отдельно устанавливать его не требуется. Храните EXE постоянно в одной папке, чтобы не сломать автозапуск и правило брандмауэра. Оба ПК должны использовать версию 0.5; версии 0.1–0.4 используют прежний протокол. Сохранённый код доступа остаётся прежним.
2. На стриминговом ПК откройте `LocalRemote.exe`, вкладку **Этот ПК управляется** → **Включить доступ**.
3. Выберите адрес Wi-Fi этого ПК. Нажмите **Разрешить доступ в брандмауэре…**, подтвердите стандартный запрос Windows. Сеть Windows должна иметь профиль **Частная**. Скрипт открывает только TCP 48930, только для этого EXE и локальной подсети.
4. Нажмите **Скопировать код**. Код содержит ключ доступа; передайте его только на свой управляющий ПК.
5. На первом ПК откройте тот же EXE → **Подключиться**, вставьте код и нажмите **Подключиться**. Можно сохранить его локально.
6. Щёлкните по удалённому экрану. **F12** отпускает удалённую клавиатуру и мышь. Для продолжения включите **Управлять** и снова щёлкните по экрану. Alt+Tab и клавиша Win при фокусе на изображении отправляются на второй ПК.

## Автозапуск

На стриминговом ПК откройте вкладку **Этот ПК управляется**:

1. Включите **Запускать доступ после входа в Windows**.
2. Для управления повышенными окнами CMD и системных утилит включите **Запускать с правами администратора**. Эта возможность доступна для учётной записи, входящей в группу администраторов Windows.
3. Нажмите **Сохранить автозапуск**. При запросе Windows подтвердите действие на стриминговом ПК под той же учётной записью. Хост запустится сразу; для перехода с обычных прав на повышенные он перезапустится, а клиент восстановит соединение.

Режим с правами администратора создаёт задание `LocalRemote-Host-<SID>` в Планировщике Windows: после входа текущего пользователя, на его интерактивном рабочем столе, с наивысшими правами. Пароль Windows не сохраняется. Программа запускает доступ и остаётся возле часов. Нет лимита времени работы и ожидания готовности сети; адреса обновляются при появлении Wi-Fi/Ethernet. Если режим администратора выключен, используется прежняя запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` с `--host --tray`. При переключении лишний способ автозапуска удаляется.

Чтобы выключить автозапуск, снимите **Запускать доступ после входа в Windows** и нажмите **Сохранить автозапуск**. Это отключает следующие автоматические запуски; текущий доступ выключается отдельно кнопкой **Выключить доступ** в окне или меню значка возле часов. Изменение или удаление задания с повышенными правами может потребовать подтверждения Windows.

Это настройка **текущей учётной записи**: после включения ПК необходимо войти в эту учётную запись Windows. Работа на экране входа и автоматический вход Windows не реализованы. Если папка программы изменилась, сохраните автозапуск снова.

После перезагрузки ключ этого ПК сохраняется. При кратком обрыве сети окно управления повторяет подключение каждые 2 секунды. При изменении IP-адреса нужно снова скопировать код; удобно закрепить адрес второго ПК в DHCP-настройках роутера. При выключении самого ПК удалённое управление недоступно.

Закрытие окна включённого хоста оставляет его в области уведомлений. **Выключить доступ** останавливает приём подключений. **Выход** в меню значка завершает программу.

## Если CMD или системное окно не принимает ввод

Windows ограничивает ввод из программы с обычными правами в окно с повышенными правами (UIPI). Это одна из возможных причин, по которой рабочий стол управляется, а отдельное окно CMD, панели AMD или другой утилиты не отвечает.

На стриминговом ПК нажмите **Перезапустить хост от администратора** и подтвердите запрос Windows локально. Если автозапуск с повышенными правами уже настроен для этой папки, используется сохранённое задание; повторный запрос UAC для запуска не нужен. После перезапуска в окне хоста должно быть **Сейчас: права администратора**. Чтобы это сохранялось после перезагрузки, включите обе настройки автозапуска и сохраните их.

Повышение прав позволяет управлять обычными окнами и окнами администратора на существующем рабочем столе. Защищённый экран подтверждения UAC, экран входа и Ctrl+Alt+Del остаются недоступны; настройки защиты Windows не меняются. Запуск под другой учётной записью не поддерживается этой кнопкой, чтобы сохранить рабочий стол и прежний код подключения. О конкретной причине отказа отдельного окна нельзя судить только по названию программы.

При отказе Windows во вводе управляющий ПК показывает подсказку; соединение и передача файлов продолжают работать.

## Звук и стрим

Программа захватывает изображение существующего рабочего стола и передаёт ввод Windows. В исходниках нет управления аудиоустройствами, изменения громкости, аудиодрайверов или вызовов RDP. Звук не перенаправляется на первый ПК и продолжает работать на втором в той же сессии Windows. Микрофон и выбранные устройства OBS программа не меняет.

Перед рабочим стримом запишите 2–3 минуты теста в OBS: подключитесь, поработайте мышью/клавиатурой, передайте файл, отключитесь, переподключитесь и проверьте запись и счётчики пропущенных кадров OBS. Это позволит оценить совместную нагрузку на GPU, CPU и Wi-Fi именно на стриминговом ПК.

## Качество изображения

В окне управления есть выбор профиля:

- **720p · 60 FPS** — по умолчанию: H.264, 1280×720, целевой битрейт 12 Мбит/с.
- **1080p · 60 FPS** — H.264, 1920×1080, 20 Мбит/с; выше чёткость и требования к сети.
- **1080p · 30 FPS** — H.264, 1920×1080, 16 Мбит/с.
- **Чёткий текст · 1080p** — JPEG с качеством 98 и целью до 30 кадров/с. Подходит для мелкого текста; скорость зависит от сети и содержимого экрана.

Пропорции монитора сохраняются, изображение не увеличивается выше исходного разрешения. Внизу окна показаны фактическое разрешение, выбранный кодировщик и получаемый FPS. Переключать качество можно во время подключения.

Хост пробует аппаратный H.264 через **NVIDIA NVENC**, затем **AMD AMF**, затем кодирование на CPU. На стриминговом ПК с RTX 3070 ожидается NVENC; проверьте название внизу окна. При невозможности запустить H.264 включается совместимый JPEG. FFmpeg запускается как скрытый дочерний процесс только на время подключения. Аудиозахват выключен.

На машине разработки с AMD RX 7700 XT получено около 60 FPS при 720p через настоящий захват рабочего стола, H.264, TLS и декодирование. Это измерение на одном ПК; результат через ваш Wi-Fi с работающим OBS нужно проверить по счётчику FPS. Если сеть перегружена, выберите 1080p/30 или 720p/60 и проверьте сигнал Wi-Fi.

## Файлы между компьютерами

1. Подключитесь к стриминговому ПК и нажмите **Файлы…** в верхней панели окна управления.
2. Слева находятся файлы **этого ПК**, справа — **второго ПК**. Откройте диск и нужную папку двойным щелчком или введите полный путь в поле и нажмите Enter. **Диски**, **Выше** и **Обновить** помогают перейти в другой каталог. Список второго ПК разбит на страницы по 100 элементов.
3. Для отправки выберите один или несколько файлов слева, откройте папку назначения справа и нажмите **Отправить на второй ПК →**.
4. Для скачивания выберите файлы справа, откройте папку назначения слева и нажмите **← Скачать на этот ПК**.
5. Дождитесь завершения: есть прогресс и **Отменить передачу**. Замена существующего файла требует подтверждения. Отмена сохраняет соединение для управления и следующей передачи.

Файлы идут напрямую по локальной сети внутри уже установленного TLS-соединения. Дополнительные порты, общие папки Windows и облако не нужны. Контрольная сумма SHA-256 проверяет полученный файл. Сначала создаётся временный файл рядом с назначением; готовый файл появляется после завершения. При отмене или разрыве соединения временный файл удаляется. После аварийного завершения процесса временный файл может остаться с расширением `.partial`.

В этой версии передаются отдельные файлы, включая множественное выделение. Для папки сначала создайте ZIP-архив. В поле **Скорость** перед началом передачи можно выбрать **Без лимита** (по умолчанию), **32 МиБ/с**, **16 МиБ/с** или **4 МиБ/с · для стрима**. Настройка действует в обе стороны. Во время передачи показаны фактическая скорость и примерное оставшееся время; после завершения — средняя скорость.

В режиме **Без лимита** скорость ограничивают сеть, диски и нагрузка на ПК. Он может занять большую часть пропускной способности Wi-Fi. Если OBS теряет кадры или управление задерживается, отмените передачу и повторите её с ограничением 4 или 16 МиБ/с. Файлы не возобновляются с места отмены. Права доступа к дискам и папкам соответствуют учётной записи, под которой запущен хост.

## Границы управления

- Поддерживаются мышь (левая/правая/средняя кнопки, колесо), клавиатура, выбор монитора, полный экран и запуск диспетчера задач.
- Программа работает после входа в Windows. При блокировке рабочего стола или защищённом окне UAC изображение и ввод приостанавливаются; после возврата на обычный рабочий стол возобновляются.
- Экран входа и Ctrl+Alt+Del не поддерживаются. Защищённые окна Windows нельзя подтвердить из этого приложения.
- Windows ограничивает ввод в программы, работающие с более высокими правами (UIPI). Для управления ими есть перезапуск хоста и автозапуск с правами администратора. Существующая запись автозапуска из версии 0.2 сохраняет обычные права, пока не выбрана и не сохранена новая настройка.
- Захват защищённого видеоконтента и некоторые аппаратные/эксклюзивные поверхности могут отображаться чёрными. При изменении состава мониторов переподключитесь.

## Соединение и ключи

Соединение TLS 1.2/1.3 с закреплением SHA-256 сертификата хоста. Сертификат проверяется по коду подключения; незнакомый ключ отклоняется. Доступ подтверждается случайным 256-битным секретом внутри TLS. До подтверждения секрета нет кадров, ввода и доступа к файлам. Одновременно подключается один зритель.

Ключ хоста и сохранённый код клиента находятся в `%LOCALAPPDATA%\LocalRemote`, зашифрованы Windows DPAPI для текущего пользователя. Не копируйте эту папку с хоста на первый ПК: только код подключения. Для отзыва старого кода: выключите хост, выйдите из программы, удалите файл `host.identity` в этой папке и вновь включите хост; на первом ПК вставьте новый код. Это также создаёт новый сертификат.

При потере соединения, снятии фокуса или F12 хост отпускает отправленные клавиши и кнопки мыши. Сеть без ответа закрывается по тайм-ауту. Приложение принимает только частные IPv4-адреса и loopback; настройки брандмауэра дополнительно ограничивают доступ локальной подсетью. Не настраивайте проброс порта в интернет.

## Если соединение не устанавливается

Проверьте, что второй ПК включён, пользователь вошёл в Windows и хост работает. Сверьте адрес в коде с адресом Wi-Fi. Обе сети Windows должны быть частными для стандартного правила. Гостевая Wi-Fi-сеть или изоляция клиентов на роутере могут блокировать соединение.

С первого ПК можно проверить порт в PowerShell: `Test-NetConnection <IP-второго-ПК> -Port 48930`. Для удаления созданного правила запустите `Configure-Firewall.ps1 -Remove` от администратора на втором ПК. Скрипт не выключает брандмауэр и не меняет профиль сети.

## Сборка и проверки

Нужен .NET SDK 10 на Windows. В корне проекта:

```powershell
dotnet build src\LocalRemote\LocalRemote.csproj -c Release
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Get-FFmpeg.ps1
dotnet run --project tests\LocalRemote.Checks -c Release
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Build.ps1
```

Скрипт по умолчанию создаёт автономную сборку x64 в `dist/LocalRemote`. `-FrameworkDependent` создаёт меньший EXE, которому нужен установленный .NET Desktop Runtime 10. Если `third_party/ffmpeg/ffmpeg.exe` отсутствует, скрипт получает его автоматически; можно отдельно запустить `Get-FFmpeg.ps1`. Архив проверяется по SHA-256 из GitHub Release. Версия и источник указаны в `third_party/ffmpeg/SOURCE.txt`. Лицензия и сведения об исходниках FFmpeg копируются в папку `FFmpeg` рядом с приложением.

Проверки используют TLS на loopback, искусственный источник ввода, настоящий захват экрана и H.264-кодирование/декодирование. Передача файлов проверяется в специально созданных временных папках, включая отмену, перезапись, пустые файлы и одновременную работу с видео. Они не отправляют реальный ввод и не меняют автозапуск/брандмауэр. Для проверки переподключения создаётся прозрачное тестовое окно приложения. Отдельно запустить видеопроверки можно параметром `-- --video-checks` после команды `dotnet run`.

Исходники: `src/LocalRemote`. Результаты проверок: `VERIFICATION.md`.

Документация платформы: [Windows SendInput и ограничение UIPI](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), [шифрованные соединения SslStream](https://learn.microsoft.com/en-us/dotnet/api/system.net.security.sslstream?view=net-10.0), [FFmpeg: захват Desktop Duplication](https://ffmpeg.org/ffmpeg-filters.html#ddagrab), [NVIDIA: использование NVENC в FFmpeg](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html).
